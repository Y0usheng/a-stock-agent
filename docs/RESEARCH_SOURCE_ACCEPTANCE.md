# 按问题取证与研究资料验收

2026-11-05。适用于默认 A 股本机订阅研究；交易权限、预算和独立风控沿用原协议。

## 修复的问题

2026-11-04 的正式研究缺少若干经理要求的经营事实，但这些事实已经存在于本机完整公告。旧选段可能选中致辞、适应症表或泛化关键词，再按片段数量压缩到一百多字。下载成功、引用有效和关键事实确实送达是三个不同检查。

`controlled-pdf-capture-v9` 增加按经营问题定位的原文窗口。银行优先资产质量、息差、资本、信用减值及业务结构；医药优先创新药收入、研发投入、授权收入和盈利质量。消费、制造、资源、水电及通用公司也有经营问题清单。当前为受控模板及每家公司最多4个经理具体问题，不是对任意问题的开放式检索。

这些窗口属于经营分析原文，不是自动生成的财务数据或摘要。表格数值仍走原有列头、单位、期间和报表范围绑定逻辑。年报解释与最新季报互补；优先排除目录、董事长/行长致辞及监管最低要求。每个原文窗口保留 PDF 页序、文本位置及哈希，入库前核对；压缩按整段取舍，不截断金额或把零碎段落拼成新的公司说法。

## 来源与输入状态

模型输入的 `source_coverage` 及本机证据审计的 `source_delivery` 分开保存：

| 状态 | 含义 |
|---|---|
| `visible_candidate_not_verified` | 候选原文已通过来源检查并进入角色输入，尚未证明回答充分或推断成立 |
| `omitted_by_input_budget` | 当前捕获正文有候选，但未进入有界输入；核心缺口应标 `input_omission` |
| `excluded_by_source_checks` | 选中后被发布时间、首次采集或其他来源检查排除，不算送达 |
| `not_found_in_captured_text` | 当前捕获正文未找到匹配，不代表公司从未披露 |

无法读取或采集失败仍保留错误，不能解释为没有信息。未来经营、增长或估值倍数属于情景假设，不应伪装成尚待找到的历史事实。候选定位不自动关闭补证任务，也不自动使研究 ready 或批准交易。

## 两层验收

1. CI 使用小型明确标记的测试源页，覆盖行业问题、来源篡改、页码错误、未来资料排除、输入遗漏以及财务基数保留，实际构造角色提示验证送达。
2. 本机验收集 `evals/fixtures/research_source_cases.json` 绑定4份官方公告及14项具体事实。先核对 PDF、提取缓存与采集回执的哈希，再通过生产选段、输入导出和来源可用性检查核对实际送达。

14项事实针对已观察到的漏读选取，不能当作全市场召回率。2026-11-04冻结输入在该定向集合中为0/14；这是故障回归的基线，不是对旧研究所有事实的评分。原件和提取缓存只留本机，仓库仅保存公开来源元数据及短事实标注。

另有6项固定断言预检，覆盖金额单位、报告期、同比/环比、计划升级为已完成、媒体来源被说成公司披露，以及“数值匹配仍不证明语义充分”。预检通过仅表示已知错误能被提示，不是通用语义蕴含准确率；复杂推断仍需独立标注或既有抽样语义复核。

```powershell
.venv\Scripts\python -X utf8 scripts/evaluate_research_sources.py `
  --source-root data/disclosures `
  --context-log logs/decisions/after_close/2026-11-04.long-v3.cn.json `
  --output logs/live/research-source-acceptance.json
```

该命令只进行工程重放，零模型请求、零订单，不改写原始决策或账本；日期和元数据用于重现输入，不构成历史交易成绩。缺少原件、哈希不符、事实漏送或预检失败均返回失败，不能跳过后报成功。原有年度EPS/净资产等财务基数也必须保留，不能只优化14项事实而损失估值输入。

每轮模型调用、令牌、字符及超时上限均未提高；来源采集仍为90秒。这里验收的是资料送达及已知错误处理，尚不证明经理会买入、盈利或具有完整行业覆盖。
