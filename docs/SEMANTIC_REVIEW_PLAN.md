# A股离线语义核验器

更新日期：2026-10-27。离线核验基础版已实现：`evals/semantic_review.py` 与 `scripts/review_evidence.py`。规则预检、结论拆分、分层抽样、独立订阅复核、原句定位和缓存均已接通。它独立生成研究报告，不接入下单流程；全文补充采集与人工标注准确率评估仍待完成。

## 使用方式

```powershell
# 默认仅规则检查；不调用模型、不联网
.venv\Scripts\python scripts/review_evidence.py logs/demo/2026-10-27.news-evidence.cn.json

# 可选订阅语义复核；本例检查全部5条拆分后的命题
.venv\Scripts\python scripts/review_evidence.py logs/demo/2026-10-27.news-evidence.cn.json --model-review --sample-rate 1
```

默认模型仍为 GPT 6.1 Sol。评审预算单独设置：最多1次请求、75秒单次超时、12000个已完成请求累计 tokens、24000输入字符、最多8条命题；可用 `--max-requests`、`--timeout`、`--token-limit`、`--input-char-limit`、`--max-claims` 和 `--batch-size` 调整。tokens 在调用完成后核对，不是在途硬上限。日常四角色的4次预算不变。

默认优先选影响 BUY/SELL 的结论、数字陈述及规则疑点，其他按稳定种子抽样10%；`--sample-rate 1` 检查全部候选，但仍受命题数量和请求预算约束。报告分层列出可用/选中/完成数量、未选中的关键ID和选中但尚未完成的ID，不把截断伪装成全覆盖。

缓存默认位于 `data/semantic_reviews.db`，绑定命题、来源片段版本、模型、推理强度、评审指令及协议；重复命中后不调用模型，也会重新核对引用。`--no-cache` 禁用缓存，`--cache` 指定路径。

报告默认生成到 `logs/reviews/`，每次保留独立文件；`--output` 可指定路径，禁止覆盖输入日志。失败/超时/无效引用保留失败报告并返回非零退出码，未验证结果不会写入缓存。

## 原句和当前边界

模型选择已给出的片段编号；宿主还原保存原句，并计算字段内的字符起止位置。公司/媒体事实与推断前提只能引用来源片段；输入缺口和实际调用角色可引用单独的本地上下文，不能将其冒充外部事实。

输入缺口核验包含该角色可见的实际片段与内容指纹，正文变化会使缓存失效，即使原结论没有直接引用该新闻。经理/风控的账户和历史记忆不在本版核验范围，涉及这些输入的缺口会要求补充实际记录，不凭部分目录确认“原Agent没有看到”。风控转述经理计划也不会直接被规则判为冒充，需要核对相关角色日志。

数值、单位、期间、同比/环比和计划/已完成的规则检查只是筛查疑点，数值表面相同不表示语义正确。公司披露若仅有媒体来源，宿主会降为待补原始披露。跨角色审批声称会单独标明。

资料不足会列入 `context_requests`，区分来源上下文与流程记录，附事件编号、原始链接及缺口；当前离线命令不自动联网下载全文。尚无独立人工标注的准确率，报告保留 `human_validated_accuracy: null` 和 `semantic_truth_verified: false`。

## 保存什么

决策输出可以只引用 `event_id`（或已有的版本化 evidence_id）；新闻内容在中心库保存一次，不必为每次判断重复下载和存储公告全文。

当前 event_id 是项目本地生成的哈希编号，不是巨潮或东方财富保证可查询的原始编号。只留下编号、删除对应内容，无法保证日后恢复当时输入；哈希本身也不能还原文本。

最小保留集：事件编号、来源、原始链接、发布时间、首次采集时间、Agent 实际读到的文本片段、该片段的内容指纹。原文的段落/字符位置可在确实读取后附加；PDF 页码只在实际解析了 PDF 时记录。

按需读取原文：涉及金额、同比/环比、报告期、重大合同、业绩变化或公告限定条件，并且该信息影响建议时，再获取相关正文、表头、单位和脚注。读取后保留所用片段及上下文；普通候选新闻不要求长期存储整个 PDF。无法取得足够上下文时，保留“证据不足”状态。

现有 SQLite 已保存标题、摘要、来源、链接、时间与指纹。它支持回查当前保存的片段，不能把未抓取的原文内容当作已读。

## 三类结论分别评价

| 类型 | 核验内容 | 不应混淆的结果 |
|---|---|---|
| 公司披露 | 直接公告是否表达该命题，主体、期间、数值、单位和条件是否一致 | “公司披露了X”不等于已独立证明X绝对真实 |
| 媒体报道/观点 | 原媒体是否这么说；发言人及“预计/可能”等限定是否保留 | 报道、转述或评论不能自动升级成公司正式确认 |
| Agent 推断/预测 | 前提是否有依据、推断是否跳跃、缺口/反证/失效条件是否明确 | 股价或盈利预测不要求逐字出现在新闻中；预测效果另用后续样本评价 |

建议增加 `claim_kind`、`source_support` 与 `inference_review` 三个独立维度。来源支持只说明前提/陈述与资料的关系，不表示未来收益已经验证。

## 核验流程建议

1. 把混合句拆成单个命题，明确谁、做了什么、时间、数量及语气。使用“逐条事实”思想，不给整篇报告一个模糊总分。
2. 先做可确定检查：编号/内容/时间边界；金额、币种、单位、期间、同比/环比、主体、预告/已实现等口径。数字相同但主体或期间不同，仍不应通过。
3. 对被抽中的命题，用独立上下文的模型核验。事实核验输入只包含命题、类型与保存片段及必要上下文；不展示原 Agent 的长篇说服性解释或后验收益。
4. 返回“支持 / 矛盾 / 证据不足 / 上下文不足”，模型选择片段编号，宿主还原原句及定位。上下文不足时生成补充资料请求，由后续执行器按需读取，不强迫模型二选一。
5. 对推断单独检查前提、假设与因果跳跃；保留允许被未来数据推翻的判断。预测到期后，再评价方向、概率校准、收益风险和成本。

模型核验可先沿用 GPT 6.1 Sol 的独立上下文；这仍有同模型偏差，不等于独立事实证明。需要人审小样本来校准核验器，不能把模型自报置信度当正确率。

## 控制时间与调用量

- 第一阶段先离线抽查已有 A股日志，核验器有单独预算，不给每个角色增加一次实时自检。现有四角色每轮4次的预算不改。
- 首先检查影响 BUY/SELL 的事实依据，以及金额、业绩等关键数字；其他陈述用分层随机抽样。5%–10%只能作为初始成本预算，不代表统计可靠性。
- 将相同来源的多个命题放在一次核验中，复用保存片段。已经审核且内容未变的片段可复用结果。
- 起步可准备30–50条人工标注命题，包含故意修改单位、期间、主体或“拟/已”语气的反例；另留未参与调试的样本检查错误放行。
- 分开记录事实支持率、归属/口径错误、关键错误漏检和上下文不足。风险定向样本和随机样本分别报结果，不把偏向高风险的抽样比例当成全量错误率。

## 研究依据与适用边界

- [FActScore](https://aclanthology.org/2023.emnlp-main.741/)：把长文本拆成可逐项核查的事实。
- [ALCE](https://arxiv.org/abs/2305.14627)：分别评价回答正确性与引用质量。
- [RAGTruth](https://arxiv.org/abs/2401.00396)：有检索资料的输出仍会含无依据或与资料矛盾的内容。
- [LLM-as-a-Judge](https://arxiv.org/abs/2306.05685)：模型评审存在位置、篇幅和自偏好等局限。

这些研究支持上述评估方法的组成思路；它们的基准成绩不能直接视为本项目中文金融核验的准确率，需要本地标注集验证。
