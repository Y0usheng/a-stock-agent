# 分红、送转与拆股核算

组合以未复权价格估值，现金分红和股份权益另行记账。前复权历史仍供研究与预测复盘使用；展示的真实价格及成交标记采用未复权口径。两份行情均须完整、同股同日并通过各自指纹校验，任一采集失败保留旧缓存，不把复权收益再加一次分红。

## 权益发生顺序

1. 股权登记日收盘后按实际模拟成交重建持股。登记日买入具有权利，登记日前已卖出及除息日后买入不领取这次分派。
2. 除权除息日确认税前应收股息与待上市送转/正向拆股股份。应收现金计入资产但不计可用现金；未上市股份按对应真实价格估值，但不可卖出。
3. 公告明确的现金红利发放日才增加现金；明确的新增股份上市日才增加可交易股份。缺少任何必需日期均停止，不默认与除息日相同。
4. 送转/正向拆股不产生买卖成交或利润。原成本在已有和待上市股份间分配；卖出原股后，尚未到账的现金或股份权利仍保留。实际成交费用和滑点照旧，不重复计费。

股息采用税前模拟，金额按人民币分四舍五入。个人投资者的股息税取决于持股期限，并可能在转让时补扣；本实现不模拟该税额，因此不是个人账户税后收益。政策依据见[财税〔2015〕101号](https://www.chinatax.gov.cn/n810341/n810755/c1797427/content.html)。相对基准是含分红再投资的理论指数；模拟账户现金不自动再投资、成交费用已扣，两者费用与再投资方式不同。

## 来源与完整性

零模型调用的宿主流程查询巨潮官方实施公告目录，并扫描最近90日的完整公告标题，识别修订及不支持的公司行为。分页按唯一公告身份与 `totalAnnouncement` 对账；`hasMore` 在末页也可能为真，不能用它判断目录是否完整。既有持仓首次接入或来源中断超过90日时，须先核对未覆盖历史，不假定过去无公司行为。

仅接受受控披露站点的原始PDF。保存原件SHA256、PDF物理页码、页面文本指纹、日期表格边界及单元格指纹。现金比例取本次实施方案，不能取旧预案、税后金额或回购股份摊薄后的除权参考比例。多行日期表头使用PDF单元格结构；无法可靠解码、比例不唯一、日期冲突或原件变更均停止自动入账。

支持普通A股现金分红、整股送股/转增及具备明确登记、生效和上市日期的正向拆股。配股、换股合并、反向拆股、零碎股尾数分配等不自动推断；遇到这些事件保留原账本和原件、暂停相关执行和严格评分。普通上市公告、限售股解禁、员工股权激励不直接作为现有普通股股东获赠股份。

## 账本、风控与历史

- 权益事件与买卖成交分表保存。结算先与原现金、股数、成本及买入日对账，再在同一SQLite事务内更新；相同输入重跑不重复派钱或增股。首次迁移先在本机 `data/backups/` 保存账户副本。
- 每日正式模拟入口在执行待排订单前核验与结算权益。权益与公司财报采集合计沿用原90秒预算，权益子阶段最多60秒；模型调用、令牌与每次模型超时限制不变。
- 应收权益纳入已冻结账户身份；现金或股份权利发生变化时，旧计划继续由账户变化检查拦截。不会自动改价、改股数或重新批准旧计划。100股买入、T+1、价格偏离、费用、流动性及单股30%约束保留，未上市股份也计入单股风险敞口。零股卖出采用保守的整仓一次清算规则。
- 历史报告过滤事件实际知悉时间与结算记录时间；后来取得的公告不能进入较早报告。已记录的组合基准起点与历史估值不重置；迟到信息导致旧估值变化时仍冻结比较，等待核对。
- 只有未复权估值及对应区间的权益来源覆盖齐备，持仓区间才恢复相对基准评分。缺数和失败保留真实日期及待核验状态。全程空仓不虚构分红。

本机原件与目录在被Git忽略的 `data/corporate_actions/`，权益流水在本机模拟账户。公开报告仅增加权益汇总，不发布原始账本、事件正文、目录或身份缓存。

```powershell
# 只刷新来源并结算到最近已收盘的真实交易日，零模型调用、零买卖
.venv\Scripts\python scripts/refresh_corporate_actions.py
# 刷新研究用前复权历史与展示/估值用未复权历史
.venv\Scripts\python scripts/refresh_trading_view.py --provider sina
```

已实连采集招商银行、恒瑞医药、宁德时代、立讯精密、中际旭创共10份实施公告；另以安集科技实际送转公告核验多行表头与上市日期。安集科技仅作为解析验收样本，未加入投资池或生产账本。单元回归验证资产守恒、登记日资格、延迟到账、卖出后保留权利、上市限制、成本分配、零股限制、重复结算、来源失败、历史可见性及冻结队列。
